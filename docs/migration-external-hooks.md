# Миграция с внешних скриптов уведомлений на native notifyBridge (#187)

## Обзор
В DSH 0.2.2+ внешние скрипты перехвата (`dsh-hooks`), рассчитывавшие на старый файл `settings.yaml`, могут завершаться ошибкой `ENOENT`.
В плагине `dsh-messenger-gateway` реализована встроенная нативная поддержка уведомлений в Telegram (`telegram.notifyBridge`), которая:
1. Не зависит от внешних скриптов, файловых настроек или сторонних плагинов.
2. Использует настроенный бот-токен и Telegram Home плагина.
3. Поддерживает события:
   - `approval` (запросы подтверждения действий `approval/asked`);
   - `task_done` (успешное завершение хода);
   - `error` (ошибка агента);
   - `blocked` (блокировка политики безопасности);
   - `max_tokens` (исчерпание лимита токенов).
4. Защищена от дублирования при повторе событий (replay protection).
5. Не блокирует ход агента (асинхронная неблокирующая отправка).
6. Автоматически исключает сессии самого мессенджера (`excludeSessionPrefixes: ['msgw-']`).

## Настройка
В конфигурации `dsh-messenger-gateway`:
```yaml
telegram:
  notifyBridge:
    enabled: true
    home: default          # имя Telegram Home (чат/канал для уведомлений)
    events:
      - approval
      - task_done
      - error
      - blocked
      - max_tokens
    excludeSessionPrefixes:
      - msgw-
```

## Предотвращение дублирования уведомлений
Если в системе был настроен внешний хук (например, скрипт в `dsh-hooks` или cron/сервис):
- **ВАЖНО**: Не удаляйте и не отключайте внешние скрипты без согласования с владельцем сервера.
- После включения `telegram.notifyBridge.enabled: true` и проверки доставки согласуйте отключение старого хука для избежания дублирования сообщений.
